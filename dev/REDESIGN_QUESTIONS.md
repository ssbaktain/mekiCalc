## ★ 함수형 계수/버프 전수 지도 (전14직업 296스킬 중 20건=6.7%, dev/_scan_functional.py)
- **# 함수형 5건**(SkillDescParam Calculate = 정적 해석 시도 가능): #TriflingWhim(윈브 3)·#BowMaster_SoulArrow(50)(bowmaster 소울애로우 버프)·#Element_Darkness_Dot(380)(나워).
- **$ 함수형 15건**(게임 런타임 상태값 = 근사 또는 리버싱):
  - `$CreatureFinalStat(...;Defence)*100/1000` **11건**: 소환수/자신 특정스탯(방어력 등) 비례 최종뎀 = 팔라딘/비숍 방어력비례 특성. ★엔진에 해당 스탯 있으면 **"스탯 비례 버프"로 근사 처리 가능**(정상상태). 예 비숍 인빈서블.
  - `$CreatureStateCount(...) * N` **4건**: 상태 스택 수 비례(콤보/빙결 카운트). ★콤보처럼 **"정상상태 최대스택" 근사 가능**(이미 stateMax 방식 보유).
- **★핵심**: 구현 5직업(hero/dk/bishop/bowmaster/나로)엔 소수만 걸림(비숍 인빈서블 버프·bowmaster 소울애로우) → 골든 대세 영향 작음(구현직업 잘 맞는 이유). 나머지는 **미구현 직업(윈브/나워/썬콜 등)에 집중** → 골든 대조 불가라 정확도 검증 자체가 막힘.
- **처리 우선순위 제안**: $CreatureFinalStat(스탯비례)·$CreatureStateCount(상태카운트)는 정상상태 근사로 데이터화 가능(설계 필요). #함수형은 SkillDescParam Calculate 정의 리버싱. 단 효과는 미구현직업 위주라 골든 대조 불가 = 실측 병행 필요.

- **진짜 원인(유력, 미확정)**: 만렙 과대는 다크플레어 하나가 아니라 **대부분 스킬에서 광범위(1.3~1.7)**. 다크플레어만 본 게 오류. 핵심 실마리=**4차 스킬 계수 성장 처리 차이**: 기존 데이터(skills_nightlord.json)는 4차 스킬 base 고정(**growth 필드 없음**), skills_v2는 clt 추출 growth=0.5 → 신규가 만렙 4차(effLevel 300)를 base×(1+0.005×300)=2.5배로 성장. 3차 이하는 effLevel 100렙=만렙 동일이라 골든 무영향, 4차만 만렙에 벌어짐 → **4차 평타(쇼다운 1.38)와 동일 패턴**.
- **미확정**: 기존 엔진이 growth 없이 계수를 어떻게 계산하는지(3차 트리플 growth None인데 100렙 골든 0.97) 미확인 → 기존 계수 로직 규명 필요. 신규 growth(clt)가 맞으면 기존이 4차 성장 누락(신규 더 정확), 아니면 신규 과대. **인게임 실측(4차 스킬 만렙 실제 계수)로 확정 필요.**
- 반례 주의: 써든레이드(4차, 0.96 정확)는 기존 dotPerCast(360×5) 큰 dot을 신규가 덜 반영해 계수 2.5배 과대와 우연히 상쇄된 것 → 개별 스킬마다 (계수성장 과대)vs(dot/버프 과소) 상쇄 정도 달라 0.96~1.68 편차.

## ★ 확인 필요(실측): 4차 평타 = 강화 평타(쇼다운/언카운터블) 모델 차이
- **나로/bowmaster 만렙 잔여 과대(1.25/1.21)의 실체**: 4차 평타가 게임에서 강화 평타로 전환됨. 나로 4차 평타=**쇼다운 챌린지(94010, 290%×5×6명 [기본공격효과])**, bowmaster 4차 평타=**언카운터블 애로우**. 신규는 clt 계수로 이를 정확 반영, 기존은 평타 계수 데이터 자체가 **없음**(skills_nightlord.json basic4 coeff=None, 옛 근사 모델).
- 신규 평타(쇼다운) 8.7e8 vs 기존 6.3e8=1.38배, bowmaster 언카운터블 9.99e8 vs 기존 5.4e8=1.85배. 신규 순계수 638%(effLevel 300 성장) vs 기존 462%.
- **판단**: 게임에서 4차 평타가 실제로 강화되므로 **신규(clt 정확 계수)가 더 옳을 가능성**. 기존 골든이 이 부분을 과소평가. 무리하게 신규를 기존에 맞추면 clt 정확도 훼손 → **인게임 실측으로 4차 평타 실제 딜 확인 필요**(게임 OFF라 보류). effLevel 300 성장이 평타에 캡이 있는지도 실측으로 확정.

## 직업특수 메커니즘 (별도 핸들러 필요 — 큰 설계)
- **콤보 스택 데이터화 완료(일반 핸들러)**: analyze가 buff의 state MaxStack>1이면 `stateMax` 기록(콤보어택 ComboAttack 5·콤보시너지 ComboAttack2 5). SkillEngineImpl이 정상상태 근사=스택당값×(stateMax+stackPlus마스터리). 반영: hero 콤보 공격력 4%×5=20%·최종뎀 5%×5=25% → hero 0.67→0.70(만렙). 다른 스택 직업 자동 적용. **남은 hero 갭**: 인핸스레이징블로우 콤보 초과중첩당 최종뎀(finalDmgPct value=None 파싱실패, comboOverBase 초과분 특수)·플래시슬래시(0.14 개별 과소). 아래는 원 조사기록:
- **콤보(hero 등) 원 조사**: state 기반 스택 시스템(clt 조사 완료). 콤보어택(12030) OnAttack 40%→ComboAttack 스택(10초), ModStatR Attack40=스택당 공격력4%·PiercePower=스택당 방관1%. 콤보시너지(13050) OnStart: 콤보어택 발동률 40→100%(SkillTriggerRatio)+13051(최종뎀 자식). 어드밴스드콤보(14060) `ModStateMaxStack ComboAttack +2`=최대스택+. 인핸스레이징블로우(14020) 콤보초과중첩당 최종뎀. **설계 방향**: analyze가 (1)state별 스택당 효과(ModStatR/ModStat with State) (2)최대스택(base StateTable + ModStateMaxStack) 파싱→skills_v2 combo필드. SkillEngineImpl이 정상상태(공격 잦음=항상 최대스택) 근사로 최대스택×스택당=상시버프. 일반 스택 핸들러(바이퍼 에너지 등 공용). skills_v2엔 현재 `$CreatureStateCount×값` 함수형이라 미파싱.
- **소환 과대**: bowmaster/나로 만렙 소환(피닉스) dps 과대. 소환 dot 스케일/가동률.
- **차징/스택 기타**: 바이퍼(에너지)·캐논 등 직업별 스택 메커니즘 추정. 콤보와 같은 핸들러 계열.
