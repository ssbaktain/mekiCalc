# DIAGNOSIS — 팔라딘/바이퍼 3배 편차의 근본 원인 (정량 규명)

README의 4개 질문에 대한 답과, 데이터로 재현한 원인 분해. 결론부터:

> **편차는 단일 버그가 아니라 "팔라딘 과대 + 바이퍼 과소"가 양방향으로 벌어진 합이다.**
> 근본 구조 원인은 "타임라인 시뮬레이터인데 proc만 정적 기댓값으로 사전 주입하는 하이브리드"
> (applyProcGrants)와 "발동 조건이 데이터 변환에서 소실"의 결합.

## Q1. applyProcGrants의 uptime = min(1, freq×dur)가 타당한가? → 아니다 (3중 과대)

1. **포화**: min(1,·)은 freq×dur ≥ 1이면 무조건 상시. 실제 확률 발동의 uptime은
   1−(1−p)^(dur 내 시행수) < 1. 홀리 차지(OnAttack 15%, 10s, 공속50%):
   엔진 1.00 vs 실제 1−0.85^15 ≈ **0.91**.
2. **freq 과대**: ON_ACTIVE_SKILL의 freq = Σ(1/모든 액티브 쿨) ≈ 0.43/s(팔라딘).
   조건("10회마다" 등)이 소실된 상태에서 이 freq가 그대로 들어가 5초 버프도 즉시 포화.
3. **경로 이원화**: 액티브 버프는 타임라인(정확), proc 버프는 정적 근사(과대) —
   같은 물리량이 두 규칙으로 계산되어 직업 구성에 따라 오차 방향이 갈린다.

## Q2/Q4. 직업별 실제 가동률을 결정론적으로 뽑는 규칙? → "규칙"이 아니라 "시뮬레이션"이 답

가동률은 발동 조건·내부쿨·스택·전투 흐름의 함수라 닫힌식이 항상 존재하지 않는다.
sim2는 가동률을 **계산하지 않는다** — proc·카운터·State를 타임라인에서 실제로 발동시키고,
가동률은 결과 리포트(관측값)로 나온다. 결정론은 시드 고정 RNG + 이벤트 전순서화로 보장.
검증: 실측 가동률이 이론값과 일치(홀리 차지 91.8%↔91.3%, 디바인 저지먼트 73.6%↔75%).

## Q3. hitDamage 곱 순서는 정확한가? → 정확 (변경 없음)

넥슨 공식 원문(전투 시스템 안내 1.3) 대비 곱 구조·상한·체감 누적 모두 일치.
sim2는 기존 hitDamage/globalMultiplier를 **그대로 계승**했다(검증된 코드 재사용).

## 재발 방지 장치 (구조적)

1. **단일 경로**: 발동은 전부 타임라인 이벤트 — 근사 경로 자체가 없다.
2. **관측 가능성**: 모든 버프의 실측 가동률·평균 스택이 결과에 나온다.
   "디바인 저지먼트 100%" 같은 값이 보이는 순간 이상 감지 가능.
3. **조용한 기본값 금지**: 해석 불가는 Warn — 이번에 기존 엔진에서도 있었지만
   보이지 않던 갭(MULTI_DAMAGE_ENTRIES 등)이 즉시 표면화됐다.
4. **SelfTest2**: 가동률 수학(포화·카운터·배타·스택소모·갱신) 9종 회귀 — 9 PASS.
